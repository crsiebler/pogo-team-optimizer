## Codebase Patterns
- Register meta-specific auxiliary inputs in `data/metas.json` using `switch_rankings_path` and `required_files`, then validate those paths in the CLI before constructing repositories.
- Keep meta config changes in `application/meta_config.py`; the CLI should only consume `MetaConfig` and enforce startup validation.
- Battle Frontier point data lives in `data/battle_frontier/` as `species,points` CSVs keyed by `parse_species()` names, and the repository should default missing species to `0`.
- Resolve switch rankings in the CLI as explicit `--switch-rankings-path` override, then per-meta `switch_rankings_path`, then the legacy Great League default path.
- Battle Frontier legality belongs in `TeamOptimizer`; pass per-row point costs from the use case so `_random_team()` and swap-based local search both share the same legality gate.
- Battle Frontier output metrics belong in `recommended_team.metrics`; keep them optional and have human-readable exporters render a conditional legality section so non-`bfmaster` metas do not need placeholder fields.
- For real-data integration coverage, instantiate the concrete CSV repositories directly in tests so `bfmaster` assertions exercise the checked-in matrices, switch rankings, and Battle Frontier points files together.
