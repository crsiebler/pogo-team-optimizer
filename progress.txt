## Codebase Patterns
- Ordered bring-6 pick-3 lineup enumeration lives in `application/lineups.py`; `OrderedLineup` canonicalizes the unordered back pair by sorted row index while preserving lead order from the input roster.
- Ordered lineup resource-path scoring lives in `application/lineups.py`; fixed paths are balanced lead 1/back 1, shield-spend lead 2/back 0, and shield-save lead 0/back 2, with lineup thresholds of `> 600` dominating and `< 400` overwhelming.
- Six-Pokemon roster objective scoring in `TeamOptimizer` should prioritize appended lineup-depth metrics before legacy full-roster coverage tie-breakers; keep score tuple indexes `0` through `12` compatible for existing metrics consumers.
- Structured `recommended_lineups` assembly lives in `AnalyzeMetaUseCase`; rank by lineup score with row-index tie-breakers, source diagnostics from `application/lineups.py`, and keep CLI/exporters from computing lineup scores.
- Bench utility diagnostics live in `application/lineups.py` and are exposed as structured `recommended_team.bench_utility`; keep them diagnostic-only and do not feed them into optimizer ranking.
- Battle Frontier lineup point diagnostics are optional use-case result fields; compute usage rates and point-aware bench warnings from viable ordered lineups without rejecting individual pick-3 lineups.
- ABC/ABB/ABA lineup shape labels are heuristic diagnostics from `application/lineups.py`; expose them on `recommended_lineups` but never use them for lineup scoring, roster ranking, or tie-breaking.
- CSV lineup-aware exports keep the stable `section,key,value` schema and use `recommended_lineup`, `recommended_lineup_resource_path`, `bench_utility`, and `bench_utility_warning` sections.
- Excel lineup-aware exports use dedicated `Lineups`, `Lineup Resources`, `Bench Utility`, and `Bench Warnings` sheets instead of overloading legacy sheets.
- Register meta-specific auxiliary inputs in `data/metas.json` using `switch_rankings_path` and `required_files`, then validate those paths in the CLI before constructing repositories.
- Keep meta config changes in `application/meta_config.py`; the CLI should only consume `MetaConfig` and enforce startup validation.
- Battle Frontier point data lives in `data/battle_frontier/` as `species,points` CSVs keyed by `parse_species()` names, and the repository should default missing species to `0`.
- Resolve switch rankings in the CLI as explicit `--switch-rankings-path` override, then per-meta `switch_rankings_path`, then the legacy Great League default path.
- Battle Frontier legality belongs in `TeamOptimizer`; pass per-row point costs from the use case so `_random_team()` and swap-based local search both share the same legality gate.
- Battle Frontier output metrics belong in `recommended_team.metrics`; keep them optional and have human-readable exporters render a conditional legality section so non-`bfmaster` metas do not need placeholder fields.
- For real-data integration coverage, instantiate the concrete CSV repositories directly in tests so `bfmaster` assertions exercise the checked-in matrices, switch rankings, and Battle Frontier points files together.
